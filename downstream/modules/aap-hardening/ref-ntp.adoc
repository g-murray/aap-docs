= NTP

[role="_abstract"]

Configure each server in the {PlatformNameShort} infrastructure to synchronize time with a Network Time Protocol (NTP) pool or your organization's NTP service.
Clock synchronization is both an operational requirement and a security control for {PlatformNameShort}.

In addition to ensuring accurate timestamps for logging, auditing, and scheduled automation jobs, NTP synchronization underpins the time-bound validation of inter-service authentication between the {Gateway} and backend services.
When the {Gateway} forwards requests to services such as {ControllerName}, {HubName}, and {EDAcontroller}, each request includes a timestamp that the receiving service validates.
If system clocks are not synchronized, the receiving service rejects requests because the timestamps exceed the allowed threshold, and authentication fails.

Clocks that are not synchronized also weaken the replay-attack protection built into inter-service communication, because the timestamp validation cannot reliably distinguish between delayed legitimate requests and replayed captured requests.

To harden your {PlatformNameShort} deployment:

* Configure the `chronyd` service on every {PlatformNameShort} node.
* Monitor clock accuracy regularly by running `chronyc tracking` on each node.
* In disconnected environments, configure an internal NTP source or peer synchronization between nodes.

You can tune the maximum allowed age for inter-service authentication headers by adjusting the `trusted_header_timeout` setting.
For more information, see link:{URLCentralAuth}/index#ref-gw-trusted-header-timeout[Trusted header timeout] in _{TitleCentralAuth}_.

For information about configuring the chrony NTP service, see link:{BaseURL}/red_hat_enterprise_linux/9/html/configuring_basic_system_settings/configuring-time-synchronization_configuring-basic-system-settings[Configuring time synchronization] in the {RHEL} documentation.
